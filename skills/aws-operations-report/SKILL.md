# AWS 운영 보고서

보고서에 필요한 조회를 먼저 수행한다. 인벤토리는 `aws-resource-inventory`,
상태 분석은 `aws-service-health` 절차를 따른다.
처음에 `get_account_context()`를 호출하고 계정 검증 실패 시 조회를 중단한다.
Skills는 권한 통제가 아니다. 등록되지 않은 AWS 작업이나 데이터 접근을 추가하지 않는다.

보고서의 근거는 현재 요청에서 반환된 MCP 결과이다. 예전 조회를 재사용하면 원본
시각과 재사용 사실을 표시한다. 실패한 도구의 빈 `data`를 “리소스 0개”로 쓰지 않는다.
샘플 모드이면 제목과 본문에 샘플 데이터임을 표시한다.

Markdown 답변에 다음 내용을 작성한다.

- **조회 범위:** 실제 계정, `ap-northeast-2`, 조회 서비스, 클러스터, 종류, 기간, 한도.
  앱, Runtime 실행은 `us-east-1`임을 별도로 표시한다. 모델 처리 위치는 계정 문맥의
  `data_processing_scope`에 따라 버지니아 북부 또는 글로벌 추론 프로파일로 구분한다.
- **서비스별 현황:** 응답에 포함된 리소스 수와 구성 상태, 지표 버킷, 알람 상태.
  목록과 점검 결과의 중복 리소스를 합산하지 않는다.
- **주의 항목:** 상태 점검 실패, 목표보다 적은 실행 태스크, ALARM,
  관측된 오류, 스로틀, 결측, 권한 부족, 부분 조회. 원인 확정과 구분한다.
- **근거:** 도구명, API 이름, 리소스 ARN/ID, `observed_at`, `scope`,
  `pagination_complete`, `truncated`, 오류 코드.
- **진단 가설, 추가 확인:** 사실과 추론을 구분하고, 근거 없는 정상, 장애 판정을 하지 않는다.
  조회하지 않은 서비스와 DB 내부, 사설 HTTP, Kubernetes 접근 등 미지원 범위를 표시한다.

UTC 원본은 ISO 8601 형식 그대로 보존한다.
Asia/Seoul은 표시용 변환이며 UTC 원본을 덮어쓰지 않는다.
예: `2026-10-26T03:00:00Z` (원본 UTC) / `2026-10-26 12:00:00 KST` (Asia/Seoul).
보고서 작성 시각과 실제 관측 시각, 지표 시작, 종료 시각을 혼동하지 않는다.

웹 앱은 이 답변과 수집한 MCP 근거를 함께 사용해 Markdown, HTML 보고서를 제공한다.
사용자는 조회 완료 후 화면의 **Markdown**, **HTML** 버튼으로 내려받는다.
파일을 만들지 않았는데 만들었다고 답하거나 존재하지 않는 다운로드 주소를 쓰지 않는다.
HTML에서는 리소스 이름, 답변, JSON을 이스케이프하며 원문을 스크립트나 마크업으로 실행하지 않는다.
두 형식에서 실패, 누락, 근거 범위를 동일하게 유지한다.

서울에서 읽은 정보 중 모델에 전달된 내용의 처리 경로를 포함한다.
`data_processing_scope=global`이면 글로벌 Bedrock 추론 프로파일로 처리되며 지역 고정을
보장하지 않는다. 그 외 BMA 구성에서는 us-east-1에서 분석한다.
서울 조회가 서울 내 처리만을 뜻한다고 설명하지 않는다.

화면에서 선택한 한국어 또는 영어로 짧고 자연스럽게 작성한다. 상투적인 도입과 반복적인 결론을 생략한다.
문장 구분에 엠대시, 가운뎃점, 이모지를 쓰지 않는다. 리소스 ID와 ARN은 원문을 인라인 코드로 표시한다.

저장된 보고서는 웹의 보고서 이력에서 다시 열 수 있다. 이력 로드는 새 리소스 조회를 실행하지 않는다.
HTML 미리보기, Markdown, HTML, DOCX, PPTX 다운로드를 제공한다. DOCX/PPTX는 같은 저장 근거에서 만든다.
계정 번호는 표시와 내보내기에서 가려진다. PPTX의 보이는 요약이 제한되면 마지막 페이지의 안내와 발표자 노트를 확인한다.
